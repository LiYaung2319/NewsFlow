# 招聘信息采集

## 接入范围

普通信息源 `zhaopin` 与 `51job` 各自返回独立结果键，复用 `/collect`、`/processor/format`。默认关键词是“计算机类”，按用户确认保留平台全部搜索结果，包含平台召回的非技术岗位；仅校验身份、必填字段和去重，不增加本地相关性过滤。

默认浏览器不加载账号登录态，不自动投递、沟通或访问每个岗位详情。采集页面自身的 JSON 响应，比从整页所有链接提取更准确，也可以获取列表响应已携带的岗位描述。

| 来源 | 搜索入口 | 监听页面响应的路径 | 已验证请求条件 |
| --- | --- | --- | --- |
| 智联 | `https://www.zhaopin.com/sou?jl=489&kw=计算机类` | `/c/i/search/positions`（POST） | `S_SOU_FULL_INDEX`、`S_SOU_WORK_CITY=489`、`pageIndex` |
| 51job | `https://we.51job.com/pc/search?keyword=计算机类&jobArea=010000,020000,030200,040000,080200` | `/api/job/search-pc`（GET） | `keyword`、`jobArea`、`pageNum` |

按真实浏览器响应识别参数，不硬编码 Cookie、签名或采集到的岗位。相同 URL 的 OPTIONS 预检及非 JSON 响应不会被当成职位列表。参数、城市或页码与预期不一致时停止，避免默默采到默认城市或重复第一页。

## 请求和覆盖范围

```json
{
  "sources": ["zhaopin", "51job"],
  "job_query": {
    "keyword": "计算机类",
    "max_pages": 3,
    "limit_per_source": 100,
    "cities_51job": ["北京", "上海", "广州", "深圳", "杭州"]
  }
}
```

`job_query` 可省略，使用上述默认值。关键词长度 1–60，页数范围 1–6，条数上限范围 1–120。网页目前通常每页 20 条；`limit_per_source=100` 不代表每次一定取得 100 条。

- 智联：全国搜索，实际有多少页面可匿名访问由网站决定。页面出现登录弹窗时停止并保留此前已取得的数据。`upstream_total` 可能只是匿名搜索窗口的数量，不能视为整个市场岗位数。
- 51job：没有确认可用的全国入口，`jobArea=000000` 实测被页面替换成默认城市。使用每组最多 5 城市的正常搜索参数，不能报告全国全量。
- 支持配置的城市：北京、上海、广州、深圳、杭州、武汉、成都、南京、西安、重庆、苏州、长沙、合肥、郑州、天津、济南、青岛、厦门、福州、珠海。城市代码已与[平台城市字典](https://js.51jobcdn.com/in/js/2023/dd/dd_city.json)核对；未配置城市返回错误，不静默替换。
- 城市列表最多 20 个，去重后每 5 个分组。`max_pages` 为所有组共享的预算，按组分配；未访问组列入 `unvisited_groups`。不无限遍历全国城市。

例如将城市改为北京、上海、广州、深圳、杭州、武汉、成都、南京、西安、重庆，并设置 `max_pages=4`，预算为两个城市组各 2 页。扩大地域优先增加城市组，不提高请求频率。n8n 可在不同低频定时任务中轮换城市组；本模块不自动调度，也不保证历史增量覆盖。

## 返回字段

`items_by_source` 保持现有协议，每条招聘结果统一保存以下业务字段；`source`、`kind` 和 `job_id` 是系统内部用于分源、识别类型和去重的辅助字段：

| 字段 | 含义 |
| --- | --- |
| `title` | 岗位名称 |
| `company` | 公司名称 |
| `city` | 城市 |
| `salary_text` | 薪资原文，保留日薪、年薪、13薪等口径 |
| `education` | 学历要求 |
| `text` | 列表响应自带的岗位描述，不保证等同完整详情页 |
| `published_at` | 上游提供的发布时间原文；缺失不推算 |
| `url` | 岗位链接 |
| `source`, `kind`, `job_id` | 内部辅助字段，不属于统一业务字段 |

薪资面议是有效值；上游未提供薪资则返回 `null`。只有标题、链接、职位 ID 有效才保留。按平台职位 ID 和规范化 URL 去重，不跨平台猜测两个职位是否相同。招聘人员姓名、头像、电话等不写入职位模型。字段缺失情况放在 `source_metadata` 中统计，不混入每条岗位记录。

`source_metadata` 包含：

- `pages_fetched`、`raw_items`、`returned_items`、`duplicates_removed`、`invalid_items`、`limit_dropped`。
- `groups`：实际查询城市组、页数、上游返回的总数、停止原因。
- `observed_cities`、`unvisited_groups`、`national_coverage`、`full_market_coverage`。
- `missing_fields`：核心字段缺失计数；`field_coverage`：各业务字段有值条数/返回总数。
- `cache_hit`、`collected_at`、`retry_after_seconds`。
- `complete_within_query`：仅指已访问完当前查询可见结果且无错误，**不是全国全量保证**。

| `stop_reason` | 含义 |
| --- | --- |
| `page_budget` / `item_limit` | 达到页数/条数预算，正常停止 |
| `upstream_end` | 当前查询可见结果结束 |
| `repeated_page` | 新页面没有新职位，避免无效继续翻页 |
| `access_restricted` | 登录、验证、限流或拒绝访问，停止并冷却 |
| `fetch_failed` | 超时、结构变化或查询条件不一致等，保留已采结果 |
| `cooldown` | 同站正在执行或处于冷却，未访问上游 |
| `configuration_error` | 城市不支持或限速状态存储不可用，未访问上游 |

招聘采集有错误但保留部分结果时，顶层 `status=partial_success`；完全失败时为 `failed`；正常空列表为 `no_data`。处理下游推送时请同时检查 `errors` 和覆盖元数据，避免把受限结果当作完整列表。

## 访问保护

配置位于 `config.py`，API 不提供关闭保护的参数：

| 配置 | 默认值 | 行为 |
| --- | --- | --- |
| `jobs_request_interval` | 12 秒 | 每站列表导航/翻页至少间隔 12 秒，加 0–3 秒抖动；代码最低允许 10 秒 |
| `jobs_cache_ttl` | 1800 秒 | 完全相同查询短期复用结果，减少重复访问 |
| `jobs_run_cooldown` | 300 秒 | 不同查询仍受同站跨任务冷却约束；普通采集错误也停止本轮 |
| `jobs_block_cooldown` | 1800 秒 | 登录/验证码/401/403/429 后至少冷却 30 分钟，`Retry-After` 更长时取更长值 |
| `jobs_response_timeout` | 30000 毫秒 | 等待列表响应的时限；超时不循环重试 |
| `jobs_state_path` | `data/jobs_state.sqlite3` | 同机进程共享站点租约、限速及缓存，进程重启不会清空冷却 |

## 登录状态适配

登录适配只作用于信息源，不改变原有新闻源的浏览器逻辑。`zhaopin` 和 `51job` 在 `SOURCES` 注册表中分别声明登录网址和会话文件；普通来源不声明 `auth` 时自动使用默认匿名上下文。两个招聘源不会共用 Cookie。

直接启动服务即可。FastAPI lifespan 在后台检查来源会话：文件缺失、JSON 损坏或内容为空时打开本机登录浏览器，不阻塞服务启动。存在可读取的会话则直接复用；文件存在并不保证远端仍认可登录。

每个来源有网站登录标签页和“登录配置”标签页。在网站完成登录后，回到配置标签页点击“登录完成，保存会话”。按钮就是管理员的明确确认，程序不再自行判断退出菜单、Cookie 或页面标志，直接原子替换 `data/auth/<source>/storage_state.json`。如果管理员未完成登录就点击，保存的自然是当前浏览器状态；这由管理员确认行为负责。

关闭任一标签页、整个浏览器或等待超过 `auth_login_timeout`（默认300秒）均不保存会话。取消后本轮服务不反复弹窗；重新启动服务会再次检查缺失会话。服务关闭会取消登录任务并清理浏览器。跨进程锁阻止多个 worker 为同来源重复开窗；强制终止遗留 `.lock` 时，确认没有登录进程后可删除该锁。

原先新增的四个认证 HTTP 路由和 `scripts/login_jobs.py` 已删除。无需调用认证 API、切换全局开关或运行登录脚本。`/collect` 仍只负责采集，未登录时返回 `auth_required`。会话文件更新会改变结果缓存键，下一次采集自动加载新文件。

采集时明确检测到登录提示会标记 `auth_status=expired` 并请求本机重新登录，每个来源每次服务运行最多自动提示一次。验证码、限流不一律当作会话过期；原有上游冷却仍生效。新会话不会解除网站访问限制。

本轮验证：27 项离线测试通过，覆盖旧认证路由移除、启动不阻塞、重复提示抑制、按钮直接保存、取消/超时不写入和原子替换。会话内容是否已登录由管理员点击按钮确认，程序不再做页面登录标志判断。

远程部署时，将本机生成的 `data/auth/zhaopin/storage_state.json` 和 `data/auth/51job/storage_state.json` 上传到远程项目相同目录即可；所有相对路径以项目根目录解析。会话迁移后可能受平台 IP/设备校验影响，需要实际采集确认。无桌面环境缺少会话时会记录浏览器启动失败，不阻塞其他来源；应提前部署会话文件。

两站可并发，每站内部严格串行。SQLite 租约防止同站同时被多个 API 请求或进程采集；任务取消后仍释放租约并保留冷却，进程崩溃后租约在 10 分钟过期。状态数据库不可用时失败关闭，不降级成无保护采集。保护范围是共享该数据库的本机进程，多机器部署需要另行共享调度。

不使用代理轮换、账号池、验证码破解或隐藏自动化特征。保守限速能降低请求压力，不能保证网站永远不限制访问。不要在遇限制时删除状态文件或循环调用接口。建议 n8n 按小时或更低频率运行，并避免多个工作流重复触发同站查询。

缓存不是永久岗位库，也不实现“仅推送新增岗位”。相同缓存结果重复送入 `/push` 仍会重复推送，调度方应根据 `cache_hit` 决定是否推送。

## 格式化与验证

继续调用 `/processor/format`，格式类型为 `collect`。两站独立消息，显示岗位名称、链接、公司、地区、薪资、经验、学历和发布时间；完整岗位描述保留在采集 JSON。消息在追加条目前检查 2000 字符预算。

离线自动化测试（不访问网站）：

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

真实浏览器 + FastAPI 接口链路验证（会访问网站，不推送）：

```powershell
.\.venv\Scripts\python.exe -B scripts/verify_jobs.py --pages 3 --limit 100
```

验证脚本检查条数、职位 ID/URL 去重、必填字段、来源、分页预算、格式化链接数、消息长度，并再次调用相同查询检查缓存。输出：

- `data/jobs_verification.json`：完整岗位、字段覆盖、错误、缓存元数据和格式化结果。
- `data/jobs_verification.md`：可阅读的消息结果。

两站均取得岗位且数据检查通过时返回退出码 0。某站因验证/冷却等未取得岗位时返回 1，并保留真实错误和另一站的结果，不伪造成功。结果目录已加入 `.gitignore`。
